# 多智能体强化学习科研助手：演进规划

日期：2026-09-12。状态：**仅规划，尚未实施科研专用能力**。

## 1. 定位与边界

目标是把 ReAgent 建设为可追溯、可复核的 MARL 科研助手，支持文献调研、方法对比、实验设计、复现检查、结果分析和论文材料整理。

当前多个 LLM Agent 的任务分工，不等于多个强化学习策略的训练。现有编排器负责科研工作流协调；未来训练应由独立、受控的实验执行器承担，不把通用 `run_code` 当作训练集群。

本轮优先改善现有 UI、会话主题、布局与底层正确性。不会安装训练框架、启动 GPU 任务、创建科研专用角色或自动提交论文。

## 2. 现状与缺口

| 能力 | 当前基础 | 尚缺内容 |
| --- | --- | --- |
| 文献入口 | arxiv_search、web_search、PDF/网页读取 | 文献库、版本去重、证据定位、来源可信度与全文阅读状态 |
| 协作 | researcher / analyst / writer / generalist、任务依赖与 Trace | 科研职责规范、可验证的交接结构、独立审查与人工决策节点 |
| 数据分析 | CSV/JSON 通用统计、受限计算工具 | seed-aware 分析、共同训练预算、置信区间、实验协议一致性检查 |
| 工作记录 | 会话、执行事件、检查点、文件沙箱 | ResearchProject / Paper / Claim / Experiment / Run / Artifact 的关联 |
| 评估 | 通用 Agent 回归评测 | 引用准确率、证据覆盖率、复现完整性、统计错误检测和成本预算 |
| 训练执行 | 无科研训练调度能力 | 白名单执行器、资源预算、环境隔离、审批、取消、失败恢复 |

## 3. 分阶段路线

### M0：先稳定通用工作台

- 完成会话主题、前端加载/异常状态、可调整布局和文件边界防护。
- 后续处理设置与 Agent 档案的损坏文件恢复、原子保存、写失败一致性；这些是当前审查记录的待办，并非本轮已完成。
- 对会话、工具、Trace 的真实状态做回归，避免把“界面显示成功”当作“执行确实成功”。
- 进入下一阶段前：已有测试稳定，错误可见，用户资料不受影响。

### M1：可溯源文献工作流（建议首个科研里程碑）

- 选定一个具体问题，而非一次性覆盖整个 MARL 领域，例如协作学习中的信用分配、通信或泛化。
- 建立论文记录：paper_id、标题、作者、来源 URL、arXiv 版本、发布日期、获取日期、文件哈希、阅读范围（元数据/摘要/全文）。
- 建立主张—证据记录：claim、paper_id、页码/章节/表号、原文短摘录或定位、归纳/推断标识、核验状态。
- 比较维度包含任务假设、训练与执行信息可见性、动作空间、协作/竞争关系、基线与实验协议；没有证据的单元格明确留空。
- 验收：给定一组确定论文，可回到原文定位每一条关键结论；检索失败与零结果严格区分；不把摘要读取标成阅读全文。

### M2：实验设计与复现协议（不自动启动训练）

- 生成可编辑的实验协议，记录研究假设、对照方法、环境版本、地图/任务、智能体数量、观测/动作定义、共享参数、奖励处理和训练预算。
- 记录代码仓库 URL、提交 SHA、依赖版本、硬件、随机种子集合、评估频率/回合数、终止与截断处理、超参数搜索预算。
- 明确消融变量，每次对照只改变被检验因素；结论区分“方法变化”与“算力/调参预算变化”。
- 对接环境时核对 API 语义；PettingZoo 的 AEC 与 Parallel API 分别面向顺序与同时动作，不应假定两者可无条件互换。[官方说明](https://pettingzoo.farama.org/)
- 验收：协议缺项会明确报警；未经用户批准，不创建有成本的实验任务。

### M3：可信实验记录与统计分析

- 先导入用户已有 CSV/JSON，不先接训练进程。
- 最小数据约定：experiment_id、algorithm、environment、environment_version、task/map、seed、training_step、metric、value，以及配置/代码/原始文件哈希。
- 以独立训练 seed 为统计单位，不能把重复评估回合或训练曲线上的每一行算成新的独立 seed。
- 比较前检查相同指标、共同 checkpoint/预算、环境与协议；不同任务分开报告，不直接混合未经定义归一化的分数。
- 先提供每个 seed 的原值、数量、均值、样本标准差、缺失/重复/非有限值告警；单 seed 不给出伪造的方差或显著性。
- 再评估引入区间估计、IQM 与性能分布等工具。少量训练运行下，点估计不能代表结论确定性；这里遵循 RL 评估不确定性的研究建议，而不是承诺自动证明算法更优。[Agarwal 等，2021](https://arxiv.org/abs/2108.13264)
- 验收：手算小样本与工具结果一致；故意构造的 seed 缺失、重复记录、指标混用和训练预算不一致均能被发现；统计输出关联原始文件哈希。

### M4：有审批与预算的实验执行器

- 由用户选择一个训练仓库和一个基准环境，按固定提交版本先接通最小复现。
- 仅执行注册过的命令模板；参数白名单、工作目录隔离、环境变量密钥隔离、资源上限和网络访问范围明确。
- 区分 dry-run、短程冒烟和正式训练。正式训练需批准算法/环境/seed 列表、GPU 时长和存储预算。
- 队列需要幂等 run_id、进程/作业句柄、取消确认、失败原因、checkpoint 与日志；界面断线不能误报训练已取消。
- 验收：短程任务可提交/取消/恢复；崩溃不会串用别的实验数据；有预算的长训练必须先经过人工确认。

### M5：科研评估与写作辅助

- 固定一组有标注答案的科研任务：检索核验、论文比较、协议缺项检查、统计陷阱识别、复现清单和结果表格。
- 分别度量工具/流程正确性与真实模型科研质量；Stub 测试通过不等于具备科研能力。
- 报告强制区分已有证据、推断、待验证假设和负结果；来源缺失时不能填入似是而非的数字或引用。
- 由人最终判断创新性、实验充分性、方法公平性及论文投稿内容；不自动冒充作者或提交出版材料。

## 4. 建议的协作职责（未来设计）

| 职责 | 输入与输出 | 默认权限 |
| --- | --- | --- |
| 文献研究员 | 问题范围 → 有来源的论文与证据记录 | 检索/只读文档 |
| 方法分析员 | 已核验材料 → 假设、对比矩阵、局限与待验证问题 | 只读文献与记录 |
| 实验设计员 | 研究假设 → 版本固定的协议与配置草稿 | 草稿写入，不启动训练 |
| 统计分析员 | 实验数据与协议 → 可复核的统计与质量告警 | 只读数据、确定性分析 |
| 审查员 | 引用、协议、结果 → 缺陷与核验结论 | 只读，不能篡改原始结果 |
| 用户 | 审查后的方案 → 范围/成本/训练/投稿决策 | 最终批准 |

角色间传递 artifact_id、来源与结构化状态，不只传大段自由文本。某一步失败应停止依赖它的结论生成，避免后续写手填补缺失事实。

## 5. 第一阶段开始前需要确认

1. 主攻问题与近期交付目标：综述、复现一篇论文，还是验证一个新假设。
2. 已有论文、代码与实验数据，以及是否涉及未公开资料。
3. 常用环境/训练仓库、设备和可用预算；在确定前不绑定技术栈。
4. 哪些外部访问和有成本操作允许自动执行，哪些必须逐次审批。

建议顺序：M0 → M1 → M2 → M3；只有记录与分析可信后再推进 M4。M5 的固定验收样例从 M1 开始积累，不等到最后才做质量验证。

## 6. 已核验参考入口

- [arXiv 官方 API 查询手册](https://github.com/arXiv/arxiv-docs/blob/develop/source/help/api/user-manual.md)：检索表达式、版本与来源元数据。
- [PettingZoo 官方文档](https://pettingzoo.farama.org/)：多智能体环境接口与动作时序。
- [Deep Reinforcement Learning at the Edge of the Statistical Precipice](https://arxiv.org/abs/2108.13264)：少量训练运行下的评估不确定性。

以上支持规划原则，不代表已经验证任何算法的最新排名、训练成本或复现结果。
